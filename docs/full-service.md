# 完整模拟电商客服闭环

## 产品体验

默认进入「商品商城」，并创建一轮新的智能服务会话。切换用户也开启新会话，不会把客服工作台的预置候接样本当成消费者首页。历史对话可在左侧主动打开，原有订单与工单保留。

1. 选商品，点击「模拟购买」，选择数量和物流场景。
2. 「生成购买确认」只创建确认卡；点击「确认提交」后才生成订单、物流记录并扣减模拟库存。没有真实支付。
3. 「查看本单物流」查询该账户的订单。点击「推进模拟物流」依次变为已揽收、运输中、派送中、已签收；每一步都有版本校验，避免重复点击跳过状态。
4. 用户问「好的，谢谢」「明白了」或点击「问题已解决」时，显示 1–5 星服务评价。待确认购买不会被感谢语自动确认。
5. 4–5 星结束本轮咨询；1–3 星进入继续处理，先提供物流、价格、退款等解决方案，不直接转人工。
6. 用户说不满意、客服忽悠或普通投诉，先询问具体问题。明确要求退款时，优先进入退款流程。
7. 未发货且在自动处理金额权限内：补充原因 → 确认取消退款 → 退款处理中 → 模拟退款完成。
8. 已发货且符合演示退货规则：补充原因和完好情况 → 确认退货 → 模拟寄回 → 包裹入库 → 验收 → 模拟退款完成。未完成前不会声称退款成功。
9. 高金额退款（默认 >500 元）、账号/支付安全、赔偿或法律风险仍由对应有权限人工处理。用户明确要求人工、连续多次无法理解或工具连续失败时，也带完整上下文转人工。
10. 普通人工候接会话可以「返回智能客服」，高风险审核不能通过此按钮绕过。

全部订单、物流、退款、评分、问题分类保存在本地 SQLite。每个类别单独归档，后续退款不会覆盖同一轮会话先前的购买与物流问题。

## 模拟履约开关

`ALLOW_MOCK_ADVANCE=true`：显示并允许演示用户推进物流和退款。关闭后后台接口同样拒绝，不能仅通过隐藏按钮绕过。

`SEED_DEMO_QUEUE=false`：默认不再创建人工候接演示样本。旧样本保留在人工工作台，消费者会话列表排除 `demo_seed` 记录。

模拟订单号使用当前机器日期生成，历史种子数据保持原演示日期。界面明确标记「模拟商城」「模拟承运」「模拟退款」，不代表真实支付、顺丰或银行系统。

## API Key 接入

先在项目根目录 `.env` 中配置，密钥不要发到公开聊天或提交 GitHub：

```dotenv
APP_MODE=local
ENABLE_LLM=true
LLM_BASE_URL=https://你的兼容接口地址/v1
LLM_MODEL=你的模型名
LLM_API_KEY=你的APIKey
```

重启 `python run.py`。运营后台 →「模型接入」查看启用状态并点击「测试模型连接」。`APP_MODE=local` 也支持直接调用兼容模型，不需要先部署 Dify；原 Dify Chatflow 仍作为可选编排路径保留，尚未实机验收。

模型用于补足口语意图理解；订单归属、商品价格、库存、确认、退款权限和执行结果都由后端确定。模型故障会展示降级说明并记录审计，优先尝试本地流程，不直接伪报成功。接口测试不会把密钥返回浏览器。

## 运营归档

运营后台 →「问题归档与评价」按商品价格、商品咨询、购买、物流、退货退款、服务投诉和安全风险筛选；展示处理状态、诉求摘要、订单、处理队列、星级统计和低分数量。

## 实测方法与边界

```powershell
python eval/run_eval.py
python eval/model_contract.py
```

第一项启动隔离的真实 HTTP 服务，执行 20 条标注核心场景及闭环安全集成检查，报告见 `reports/eval.md`。新的策略对比旧版本：首次知识未命中先追问，常规售后先补充信息，不以转人工作为默认成功路径。

第二项使用本地伪模型服务验证兼容接口、环境变量注入、口语意图分类和连接测试。它不是外部真实模型测试，不能据此宣称真实模型准确率、幻觉率或线上自动解决率达标。实际外部提供方需在用户配置 Key 后单独验证。
