# 多用户、商品与队列交互升级

## 可点击演示

顶部「演示用户」可切换李女士、张先生、王女士。每位用户各有两个不同型号的订单，会话、订单与工单按服务端 Token 绑定身份隔离，不接受浏览器传入 user_id 冒充其他用户。

|演示用户|订单商品|款式 / 颜色|订单金额|
|---|---|---|---:|
|李女士|AF-35 / AF-45|轻巧经典款白色 / 可视升级款奶油白|398 / 469 元|
|张先生|EK-17 / AF-55|恒温款雾灰色 / 家庭大容量款苔藓绿|199 / 598 元|
|王女士|AF-65 / TO-20|双区旗舰款曜石黑 / 双槽复古款复古红|799 / 269 元|

所有参数和价格均为本课程项目构造的演示数据，不代表真实品牌商品。

消费者端在「人工服务方向」中选择六类技能队列，再点击转人工。客服工作台左侧队列可点击筛选，右侧可选择目标队列并确认转派；高风险会话锁定审核队列。重复接管返回已有接管状态，不重复发送欢迎语。

## 价格追问

- 选中 AF-45 订单后问「多少钱」，回答该订单商品金额 469 元。
- 催单结果之后问「多少钱」，保留订单上下文。
- 明确问「AF-55 多少钱」，即使前面选了 AF-35，仍以明确型号为准，回答演示售价 598 元。
- 没有任何型号上下文时问「多少钱」，先展示商品选择卡，不猜价格。
- 先问「AF-55 容量多大」再问「多少钱」，使用同一商品上下文。
- 不指定型号问容量或功率，展示多型号概览，避免把 AF-35 的参数当作所有型号的参数。

报价属于 L1 确定性只读商品/订单查询，不依赖模型生成价格。知识参数仍仅从对应型号的已发布知识检索。

## 数据迁移与验证

启动时自动追加用户、商品和新知识，只在首次 catalog-v2 迁移时更新旧演示的第二笔订单和水壶种子。保留已有对话、工单和运营知识版本；旧对话的订单卡从当前订单数据展示正确型号。初始人工队列有张先生、王女士的两个明确标记样本；设 `SEED_DEMO_QUEUE=false` 可停止初始化样本，不会删除已存在记录。

`python eval/run_eval.py` 运行 20 条核心场景与 31 项安全集成检查，包含多用户并发隔离、价格上下文、不同型号检索、未知型号不猜测、转派、高风险防绕过、工单归属及接管幂等。
